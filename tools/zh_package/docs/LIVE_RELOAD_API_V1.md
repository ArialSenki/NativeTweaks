# 可选的实时重载 API v1

NativeTweaks 无需修改模组的 DLL 就能发现并编辑其 INI。但要让修改立即生效则不同：
模组必须提供一个安全的重载途径。NativeTweaks 绝不会卸载模组 DLL、猜测内存修改，
也不会假定重新读取 INI 是安全的。

在模组项目中包含 `include/erms_live_reload_v1.h`，并导出其中声明的两个函数：

- `ERModSettingsHub_RequestReloadV1(ini_path)` 接收已保存 INI 的 UTF-16 路径，
  并返回非零的请求 ID。如果 DLL 无法接受该请求，则返回 0。
- `ERModSettingsHub_GetReloadStatusV1(request_id)` 使用头文件中的常量报告状态：
  处理中、已应用、已拒绝、需要重启或失败。

NativeTweaks 在后台保存线程中、原子替换 INI 完成之后调用这些导出函数，并最多轮询
五秒。模组可以在该线程中同步解析和校验，也可以把工作排入自己的线程，并在安全时机
发布完整的配置快照。请让请求结果在至少五秒内保持可查询。

## 安全要求

- 确认 `ini_path` 是该 DLL 自己的配置文件。
- 先将完整的候选配置解析到临时存储中。数值无效时予以拒绝，且不改动当前生效的配置。
- 以原子方式、或在模组更新循环的安全时机发布完整配置。不要在游戏代码读取共享设置时
  逐个字段地修改它们。
- 只要有任何请求的设置无法在本次游戏过程中安全修改，就返回 `RESTART_REQUIRED`。
  不要卸载或重新加载 DLL。
- 不要在保存回调中调用渲染或游戏 UI 函数。该回调不在菜单线程上，但仍运行在游戏进程内。
- 导出函数应尽量简短。耗时工作请先返回请求 ID 并异步完成；NativeTweaks 最多轮询五秒。
- 在游戏进程的整个生命周期内保持 DLL 已加载。NativeTweaks 不负责模组 DLL 的生命周期。

未导出这两个函数的旧 DLL 和模组仍可保存 INI，但 NativeTweaks 会提示需要重启。
仅凭 INI 本身无法告诉 NativeTweaks 哪些数值可以安全地实时修改，以及该如何应用。
